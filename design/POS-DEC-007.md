# POS-DEC-007 — Authorize milestone 8: stored files, upload queue and backup packaging (IB-19, IB-20, IB-23)

Date: November 16, 2026 · Decided by: **Surely Win Dilag**, product owner and sole engineer
Follows [POS-DEC-006](POS-DEC-006.md). Tracked as GitHub milestone "M8 Artifacts, sync queue, backup packaging".

## Decision

1. **Milestone 8 authorized**:

   | Backlog item | Scope |
   |---|---|
   | IB-19 | Artifact materializer: turns every artifact intent (sale JSON, correction JSON, report CSV/PDF) into a file under `artifacts/` by temp-write, flush, hash and rename, then marks it Ready. Crash after rename is reconciled by hash. A missing file is regenerated only if the bytes reproduce the stored SHA-256; otherwise the artifact is held, never overwritten. |
   | IB-20 | Durable upload queue: claim with lease (120 s, renewed every 30 s), lease owner + version checks, attempt history, full-jitter backoff, Retry-After, manual retry that keeps the remote identity, Failed and RecoveryHold states. Remote identity is allocated before the first send, written to the database and to a flushed, hash-chained upload-identity journal (`data/uploads.journal`); every retry reuses it. Success needs a read-back of identity, size and checksum. |
   | IB-23 | Backup package: the verified snapshot folder is packaged as one `.zip` with the manifest, number journal and upload-identity journal, checksummed and renamed only when complete. Retention keeps at least seven generations, never deletes the two newest verified or any backup still waiting to upload. Free-space warning and refusal. In-process scheduler with due keys: daily backup once per business day, monthly report catch-up for each completed month, and stored CSV/PDF files for each business-day close. |

2. **Implementation choices**:
   - **No Google account (POS-DEC-002):** the queue uploads through a remote-store port. The Test profile gets a **simulated destination**, a local folder `simulated-drive/` that behaves like Drive (pre-generated IDs, create with ID, read-back of metadata and bytes). Tests use an in-memory fake that can fail after a successful create. The real Drive adapter is IB-21 (milestone 9).
   - **Destination binding:** a new single-row `CloudStorageSettings` table (as in the database design) holds the binding ID, provider and enabled flag. Queue rows are created by the worker for Ready artifacts while a binding is enabled, rather than inside the sale transaction; the artifact intent written with the sale is the durable record, so nothing is lost while sync is off. Changing destination never replays old files automatically.
   - **Artifact holds:** a new `ArtifactHolds` table records why an artifact cannot be materialized (for example, the stored file differs from the regenerated bytes). `ArtifactRecords` keeps only Intent/Ready, so its baseline guard triggers stay unchanged.
   - **Backups stay rows; files are pruned:** retention deletes old package files but never the `Backups` row, which keeps its audit trail. The backup's artifact is created Ready with the package hash.
   - **Restore** accepts a package (`.zip`, extracted to a recovery work folder) or a folder from milestone 5. After a restore, queue rows without a remote identity adopt one from the upload journal when it matches; if the journal is missing while the database shows uploads, new creates are held.
   - **Scheduled jobs run under a signed-in user** with the needed capability, since every report run and backup records who made it. If no such user is signed in, the job waits and the status shows it as due.
   - **Status screen:** a small "Backup and sync" card in Settings (counts, oldest pending, last success, holds, run now, retry failed, enable/disable the simulated destination). The full sync screens are IB-22 (milestone 9).

3. **Deferred:** Google OAuth and the Drive adapter (IB-21), full sync/status screens (IB-22), replacement-device recovery drill (IB-24), settings and users UI (IB-25).

4. POS-DEC-002 constraints continue: Test profile and synthetic data only; no real printer, Google account or tax data; production activation disabled.

Work stops after milestone 8 for a report.
